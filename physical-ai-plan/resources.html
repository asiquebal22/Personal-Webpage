Environment and provenance rules

  1. Keep the learning sandbox and research training environments separate. Do not force older Spinning Up dependencies into the main robot stack.
  2. Use repository setup instructions for your platform. Pin the working commit and resolved dependencies after the first successful run.
  3. Use local CPU/MPS for small exercises; measure GPU requirements before selecting a large predictor or policy.
  4. Keep raw robot logs and large checkpoints out of the website repository. Publish only the approved artifact and documented samples.
  5. Record code revision, seed, config, split manifest, model/data source and actual device in every run.
