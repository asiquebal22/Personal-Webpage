Research engineering and deployment

Can someone else rerun, debug and trust your experiment?

CriticalIntegrated study hoursConnected lab 05 →

What to understand

  • PyTorch shapes, autograd boundaries, checkpointing, evaluation mode, vectorized environments and reproducible random generators.
  • Dataset manifests, immutable split IDs, versioned configs, model hashes and replay-buffer provenance.
  • Training throughput, GPU memory, inference latency, parallel rollout generation and stale observations.
  • Robot interfaces, observation/action contracts, episode logging, reset time, command limits and recovery rollback.

What to derive or explain

  1. Trace batch×time×feature dimensions through model training, imagined rollout and policy execution.
  2. Identify every source of randomness and every timer in one adaptation episode.
  3. Explain how you would diagnose good synthetic returns but poor hardware results.

Connect it to code

Use configuration-driven runs, save artifact manifests, and replay an episode with timestamp and action-unit checks. Log every real trial, including aborted trials, calibration and resets. Build a minimal dataset reader before expanding collection.

Interview retrieval practice

  • How do you profile a slow imagination-training loop?
  • What belongs in a checkpoint besides network weights?
  • How would you reproduce a failure that only occurs on the physical arm?

Mastery check

A clean-machine setup recipe and an experiment bundle that includes configuration, seeds, code revision and outcome labels.
